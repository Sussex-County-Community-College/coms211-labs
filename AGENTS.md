# Task Tracker lab boundaries

The student is the engineer and approves each implementation step.
Goal -> inspect -> plan -> act -> observe -> revise -> repeat -> report.

First inspect README.md, requirements.md, source, and tests. Propose a plan before editing.
Implement only the student's approved mark-complete step. Preserve add/list behavior.
Allowed changes: src/main/java/, src/test/java/, README.md, and student evidence files.
Do not change pom.xml, database scripts, requirements.md, or this file without instructor approval.
Do not remove or weaken starter tests. Keep SQL values parameterized and close JDBC resources.
Do not read credentials, change accounts, reset data, install software, commit, or push.
The student runs database setup and GUI checks. Request sanitized error summaries as needed.
Report changed files, checks actually performed, failures, and checks still needed.
Do not claim UI or persistence verification based only on unit tests.
